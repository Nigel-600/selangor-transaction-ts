# Panel data analysis of a multi-store beverage chain in Selangor, Malaysia

Statistical and machine-learning analysis of daily beverage sales across stores in
Selangor (2023–2024), investigating whether historical discount depth Granger-causes
revenue at the store and drink level, once cross-sectional dependence from common
regional/company-wide shocks is purged.


## Research problem

The research project addresses the apparent Granger-causation of historical discount as a spurious artefact of a latent confounding common factor shared across panels, when modelling revenue generated per-store and per-beverage.

This research also attempts to capture the structural breaks and seasonality by residual learning via LightGBM that would otherwise explode parameter dimensionality when panel-specific structural or seasonal dummies are included. Hence, a CCEMG-LightGBM hybrid stack is proposed in this research as one of its promising and significant developments.

## Methodology summary

- **Data**: daily transactional beverage sales, aggregated into two panel formats —
  store-wise and drink-wise — with revenue and discount summed per period, plus
  engineered lag (up to 7) and rolling-mean features.
- **Cleaning**: merged the "Dark Choco Latte"/"Dark Chocolate Latte" naming split,
  dropped negative selling-price records, and excluded low-sample-size store panels
  (Store indices 29, 31, 38) from causality tests.
- **Structural breaks**: Bai–Perron breakpoint detection on total revenue, cross-checked
  against Ramadan periods and a mid-2023 unit-price increase.
- **Heterogeneity tests**: Hsiao F-tests (pooled vs. fixed-effects vs. fully
  heterogeneous OLS) and Mundlak's auxiliary regression (random- vs fixed-effects),
  both rejecting pooling/homogeneity — motivating panel-specific slopes and fixed
  effects.
- **Granger causality**: Dumitrescu–Hurlin Homogeneous Non-Causality (HNC) test, run
  both on raw residuals (inflated by cross-sectional dependence) and after a CCEMG
  projection that purges the latent common factor — see Section 3.1–3.2 of the report.
- **Machine learning**: LightGBM (GOSS + EFB) tuned with Optuna (TPE sampler), trained
  either "full-stack" (raw panel features) or "hybrid" (on CCEMG residuals), evaluated
  with RMSE and explained with SHAP/PDP.

## Requirements

- **R** (≥ 4.x) with packages: `plm`, `dplyr`, `ggplot2`, `tidyr`, `reshape2` (for
  `melt`), `usethis`, and whatever `scripts/packages.R` / `scripts/functions.R` load
  (e.g. a Bai–Perron breakpoint package such as `strucchange`).
- **Python** (≥ 3.9) with `lightgbm`, `optuna`, `optuna-dashboard`, `pandas`,
  `numpy`, `shap`, `scikit-learn`. Dependencies are expected to be managed via
  [`uv`](https://github.com/astral-sh/uv) if available (the Makefile auto-detects it
  and falls back to plain `python`).

## Usage

### 1. Clean data and build panels

```bash
make clean-data
```

Runs `scripts/clean_sgor_script.py` (drops negative-price rows, merges the Dark
Choco/Chocolate Latte naming discrepancy, etc.) followed by `scripts/get_panels.py`
(aggregates the cleaned transactions into store-wise and drink-wise panel CSVs with
lag/rolling features).

### 2. Econometric analysis (R)

Run `r_analysis.R` interactively or via `Rscript`. It expects `data/panels/...` to
already exist (i.e. run `make clean-data` first). Key outputs:

- `store_ccemg` / `drink_ccemg`: CCEMG (`pcce`) fits — used as the "common-factor
  corrected" model referenced throughout the report.
- `store_vcm` / `drink_vcm`: heterogeneous fixed-effects panel regression models (`pvcm`).
- `data/residuals_store_panel.csv` (and the drink-level equivalent): CCEMG residuals,
  consumed downstream by the LightGBM **hybrid-stack** models.
- Panel Granger non-causality tests (`pgrangertest`, Ztilde/Wbar statistics) at lags
  1–7, before and after the CCEMG projection, with bar-plot visualisations of
  individual panel p-values (as in Appendices H and I of the report).
- Maddala-Wu panel unit-root diagnostics on CCEMG residuals.
- QQ-plot and residual-vs-index diagnostics per store/drink, written to
  `figs/resids/<k_rev>/`.
- Pairwise cross-sectional correlation heatmaps (VCM vs CCEMG) illustrating how much
  the CCEMG projection reduces cross-sectional dependence.

Adjust `k_rev` / `k_disc` at the top of the script to change the number of revenue /
discount lags used in the panel formula (the report uses 7 for both).

### 3. Tune LightGBM (Python / Optuna)

```bash
make tune-lgbm study_name=LightGBM_tuning dir=optuna n_tune_trials=250 \
    model_type=0 residual=0 transform=0 use_panel_id=0
```

Runs `scripts/lightgbm_script.py`, which launches an Optuna study (default 100 trials
via `n_tune_trials`, 250 in the report) over the hyper-parameter grid in Table 7 of the
report (`feature_fraction`, `max_depth`, `num_leaves`, `min_child_samples`, `num_tree`,
`lambda_l2`) using the TPE sampler.

Makefile variables:

| Variable          | Meaning                                                                 | Default          |
|--------------------|--------------------------------------------------------------------------|------------------|
| `study_name`       | Optuna study name                                                       | `LightGBM_tuning`|
| `dir`              | Directory for the Optuna storage (SQLite DB)                            | `optuna`         |
| `n_tune_trials`    | Number of Optuna trials                                                 | `100`            |
| `model_type`       | Panel type to model, e.g. store vs. drink panel                         | `0`              |
| `residual`         | `1` to train the **hybrid-stack** model on CCEMG residuals instead of raw revenue (`0` = full-stack) | `0` |
| `transform`        | `1` to apply per-panel standardisation of target/lags (needed for drink panels — see Section 3.3) | `0` |
| `use_panel_id`     | `1` to include a categorical store/drink identifier as a LightGBM feature | `0`            |
| `loss`             | Loss function selector (e.g. RMSE vs. pinball loss)                     | `0`              |

### 4. Run inference / evaluation

```bash
make run-lgbm-inference inf_dir=optuna inf_study_name=LightGBM_tuning \
    inf_model_type=0 inf_log_dir=logs inf_residual=0 inf_transform=0 inf_use_panel_id=0
```

Runs `scripts/lightgbm_inference.py` against a previously tuned Optuna study, loading
the best-found hyper-parameters and logging evaluation output (e.g. RMSE, SHAP/PDP
artefacts) to `inf_log_dir`.

### 5. Inspect Optuna trials

```bash
make open-dashboard path_to_db_file=optuna/LightGBM_tuning.db
```

Opens the Optuna dashboard (via `uv run optuna-dashboard` if `uv` is available,
otherwise `optuna-dashboard` directly) to browse trial history, e.g. the RMSE CDFs
discussed in Figures 15–16 of the report.

> Note: `path_to_db_file` is not declared with a default in the Makefile — pass it
> explicitly, pointing at the `.db` file created under the `dir` used for tuning.
